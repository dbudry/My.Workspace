# Azure production setup

Optional path once **local** setup works ([SETUP-FROM-SCRATCH.md](SETUP-FROM-SCRATCH.md)).

My.Workspace is designed for **self-hosters**: this repo’s `master` release flow does **not** deploy to a shared Azure subscription. You provision your own resources, then deploy with your pipeline or zip deploy.

## Golden path

| Step | What |
|------|------|
| 1 | Install [Azure CLI](https://learn.microsoft.com/cli/azure/install-azure-cli) and run `az login` |
| 2 | Preview: `.\Scripts\Setup-Azure.ps1 -WhatIf` |
| 3 | Create: `.\Scripts\Setup-Azure.ps1 -NamePrefix my-workspace -Location eastus` |
| 4 | Finish Google redirects + Function settings (script prints the list) |
| 5 | Deploy client + Functions; open site → `/setup` → first Admin |

## What the script creates

```powershell
.\Scripts\Setup-Azure.ps1 -WhatIf
.\Scripts\Setup-Azure.ps1 -NamePrefix my-workspace -Location eastus
.\Scripts\Setup-Azure.ps1 -SkipSql   # bring your own database
.\Scripts\Setup-Azure.ps1 -GoogleClientId "....apps.googleusercontent.com" -GoogleClientSecret "..."
```

| Resource | Name pattern | Notes |
|----------|--------------|--------|
| Resource group | `rg-{prefix}` | Holds everything |
| Storage account | `st…` | Required by Functions; calendar queue/locks auto-create here |
| Application Insights | `appi-{prefix}` | Logs / Admin logs page |
| Function App | `func-{prefix}` | Consumption, .NET isolated; managed identity enabled |
| Static Web App | `swa-{prefix}` | Hosts Blazor WASM; proxy `/api/*` to Functions |
| Azure SQL | `sql-{prefix}` / `MyWorkspace` | Optional (`-SkipSql` to skip) |

Suggested GitHub Variables (if you wire CI):

| Variable | Example |
|----------|---------|
| `AZURE_RESOURCE_GROUP` | `rg-my-workspace` |
| `AZURE_SWA_NAME` | `swa-my-workspace` |
| `AZURE_FUNCTION_APP_NAME` | `func-my-workspace` |

## After the script — remaining checklist

### 1. Google Cloud

Add production redirect URIs on your OAuth Web client ([SETUP-GOOGLE-CLOUD.md](SETUP-GOOGLE-CLOUD.md)):

- `https://<your-swa-host>/authentication/login-callback`
- `https://<your-swa-host>/settings`

Enable **Google Calendar API** / **Drive API** if you need those features.

### 2. Function App settings

Confirm in Azure Portal → Function App → Configuration:

| Setting | Notes |
|---------|--------|
| `AzureWebJobsStorage` | Set by script |
| `FUNCTIONS_WORKER_RUNTIME` | `dotnet-isolated` |
| `DefaultConnection` / `ConnectionStrings__DefaultConnection` | Set when SQL is created; use `Authentication=Active Directory Default` with MI |
| `Google__ClientId` | Same OAuth client as the SPA |
| `Google__ClientSecret` | OAuth secret |
| `Google__TokenEncryptionKey` | Generated by script (do not lose it if users already connected Calendar) |
| `Auth__AllowedEmailDomains` | Optional env override; otherwise `/setup` stores domains in the DB |
| `Google__WebhookUrl` | Optional public webhook URL; if empty, watch renewal uses `https://{WEBSITE_HOSTNAME}/api/googlecalendar/webhook` |

### 3. SQL managed identity (when using Azure SQL)

1. Function App → Identity → System assigned = **On** (script enables this).  
2. In the database, create a user for the Function App name and grant `db_datareader` + `db_datawriter` (see [DEPLOYMENT.md](DEPLOYMENT.md)).  
3. For Admin → Logs, grant **Monitoring Reader** on the App Insights resource.

### 4. Deploy

Deploy the Blazor WASM client to the Static Web App and the Functions project to the Function App (your CI or manual zip/SWA deploy). Details: [DEPLOYMENT.md](DEPLOYMENT.md).

Link the SWA to the Function App so `/api/*` is proxied (same-origin). Client `ApiBaseUrl` should stay relative `api/` for production.

Set `Authentication:Google:ClientId` in the client build (`wwwroot/appsettings.json`) before publish.

### 5. First production admin

1. Ensure allowed domains cover your admin email (`/setup` or `Auth__AllowedEmailDomains`).  
2. Open the production URL → `/setup` if no users exist.  
3. Complete wizard / sign in — first user is Admin.

### 6. Calendar (optional)

No manual queue creation. After connect in **Settings**, use **Admin → Debug → Google Calendar** for status, test enqueue, and renew watches.

## Security notes

- Do not set `Auth__AllowedEmailDomains=*` on a public URL unless you understand that any Google account can attempt first-user bootstrap on an empty database.  
- After the first admin exists, unknown users receive 403 until invited.  
- Never commit Function App secrets or `local.settings.json`.
